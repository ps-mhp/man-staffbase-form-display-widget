# FAQ

**In the plugin widget, a red warning appears for "Forms" — why?** 
intent. The Staffbase plugin widget embeds forms as an iframe with fixed
height. As long as this widget is installed, it warns there and points to
on "FormDisplay" — the form belongs directly on the page in the MAN CI. 

**The widget says "The form could not be loaded" — why?** 
In most cases, the form is not (or no longer) published or the ID points to a
deleted installation. open the form in the Forms app and enter the ID with the
Compare widget configuration. 

**Readers will see "You have already submitted this form".** 
That's the form's once-reply rule, not the widget. Whether
multiple responses are allowed in the settings of the Forms app
. 

**Why doesn't my form appear in the drop-down list?** 
The list shows only forms with administrative rights and the most recent
changed 100. In both cases, inserting the form address into
the field. 

**Are all question types supported?** 
Text input, paragraph text, date, selection list, single and multiple selection
are displayed natively in the MAN CI. A question type unknown to the widget
appears as a text field so that the question remains answerable; File uploads
does not currently support the widget. 

**What language does the form appear in?** 
The form app already provides the questions in the language of the reader
Person. The widget's controls (submit, error messages) are
English, as in the Events widget. 

**Does the answer count towards the normal evaluation?** 
Yes. The widget sends to the same form app; recipient emails, webhooks, and
The response list behaves as when filling in the form area.
